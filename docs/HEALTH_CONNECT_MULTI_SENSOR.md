# 多传感器来源与 Health Connect

两个同时采集的 CGM 各自计算、保存和上传。主传感器选择继续决定主显示及原有报警策略；不平均两个 CGM，也不让其中一个传感器关闭另一个传感器的 Health Connect 上传。

## 身份与兼容

- `health-connect-sources.db` 为每个规范传感器身份持久保存随机 UUID。来源短 ID 为 `cgm-` 加 UUID 前八位；列表顺序、主传感器选择、重连和重启不改变 UUID。短 ID 如有歧义不自动选中，可用完整 UID 查询。
- 可复用发射器 UUID 与佩戴周期分开。来源目录被动读取厂商确认的开始时间；鱼跃直接沿用已有 wear UUID 和已归档时间锚点。旧历史无法确认归属时保持未知。该目录不触发配对、启动、结束佩戴或物理重置。
- Health Connect 没有供 BloodGlucoseRecord 使用的任意标签。`Device.manufacturer` 使用已知厂商，`Device.model` 使用已知型号和本地来源短 ID，例如 `CT4 · cgm-xxxxxxxx`；未知厂商/型号保留未知。设备信息在其他应用里是否可见由对方决定。`DataOrigin` 仍由 Health Connect 设置为 JugglucoNG。
- 保持 `juggluco-ng:glucose:<原有 sensorName>:<Unix 秒>`。从旧 revision 数据库恢复原有上传别名；不用新 UUID 替换已有记录 ID。同秒两个传感器依然有两个记录 ID。
- `health-connect-versions.db` 从 v1 加一列 metadata 到 v2，保留原 ID、数值和版本。血糖或设备信息变化时才提升版本；失败重试复用版本，手机时钟回退也不会降低版本。

## 同步范围与触发

本地 CGM 写入后继续调用现有 Health Connect 桥接入口。后台按原生传感器合并请求并串行发送，每块最多 500 个原生采样槽；成功提交后才确认游标。一个传感器失败不会阻塞后续传感器，下一次本地写入或启动会重试未完成部分。关闭开关会取消工作；权限申请仍从初始化/设置入口进行，后台各来源不会重复弹出授权界面。

Health Connect 初始化和授权完成后枚举所有仍保留原生 poll 历史的来源，包括已结束传感器，补齐以前被单传感器规则抑制的记录。新来源/厂商型号完善会重放该传感器已有有效 poll 数据以更新设备信息。手动“补传全部来源”重置的是全部导出游标，再使用同样记录 ID 重放；不重算血糖、不改时间、不操作物理传感器。

Health Connect 保持原有 `streamfromSensorptr` 数值/本地校准路径；只同步有效原生 poll 采样，不将 Raw-only 无效值、预热无效值或三星读取缓存写入血糖。原生 poll 已不保留、仅存于 Room 的旧记录和仅扫描得到的历史不是这条桥接入口的上传范围。单按钮 Agent 导出仍包含全部有效 Room 血糖、全部来源和已缓存三星数据。

## 页面和 Agent 导出

传感器详情中“查询该传感器的健康数据来源”进入“健康数据与血糖 → 血糖来源”。可输入来源短 ID、完整 UID 、完整 Health Connect `clientRecordId` 或本应用上传后保存的 Health Connect 服务端记录 ID；来源查询浏览最近 300 条 Auto/Raw，记录 ID 查询定位具体 UTC 时刻与已知佩戴周期、最近提交状态。提交状态指本应用最近上传请求成功，不能证明对方记录未被用户删除。

`glucose-sources.jsonl` 为全量 Agent ZIP 增加来源目录；每条血糖带 `source_uid_alias`、`local_lookup_id`、可空 `wear_session_alias`。UUID/佩戴周期在导出中使用已有 HMAC 别名，不导出完整 MAC、二维码或原始 Health Connect 记录 ID。随机短 ID 用于本机查询；时间仍为同一 UTC epoch，原有 Auto/Raw 通道不重复校准。提供的 record schema 包含这些可选字段。

## CT4 实际计算诊断

“探头二维码与算法状态”中的 K0 是当前配置值。新增“最近实际计算”来自同一条 MODEL 计算时捕获的不可变帧：ID/时刻、实际 K0、Iw、原始/平滑温度、温度因子、步长、前值、滤波前后数值、本地校准后的值、live/完整历史/不完整历史路径和本次内存模型起点。读取诊断不会再次计算或改变滤波器；恢复的旧连续状态没有起点证据时明确显示未知。

计算示例：K0 1.19、Iw 15.75 nA、有效温度取 31.7°C，当前模型未滤波值为：

`15.75 / (1.2 × 1.19) × [1 - 0.04593 × (31.7 - 32)] ≈ 11.18 mmol/L`。

这个示例只核对本地公式，不能证明官方 App 使用相同采样或系数/温度/滤波。R、电压模式只影响当前实现的 Raw 线性通道；MODEL 使用 K0。更换二维码清旧实时模型，手动历史使用独立重放模型；完成历史重算不会把历史滤波器覆盖到实时滤波器。有效温度和实时构建起点需查看新增实际帧。没有证据支持修改 K0、加固定比例/数值补偿、平移历史时间或宣称已复现官方算法。

## 验证边界

主机测试覆盖多来源同秒、持久身份、别名兼容、不同佩戴周期、失败提交标记、metadata 修订和 v1 兼容迁移、跨时区 epoch、全量 ZIP 来源目录、CT4 实际计算帧和既有回填不推进实时滤波的回归。签名 arm64 releasedub 编译与 APK 校验记录在本地交付报告中。

用户 S23 Ultra/Watch8/CT4 未连接到此工作环境；多 CGM 对 Health Connect 的真机接受情况、对方设备信息展示、扫码后与官方同 ID 的算法差异仍需真机核对。三星继续使用已确认的直接读取/全量导出方案，SDK/AAR 和个人安装包只在本地，公开分支不含 SDK。
