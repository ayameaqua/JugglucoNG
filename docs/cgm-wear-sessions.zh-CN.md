# 可复用发射器的佩戴周期修复

2026-10-09，fork 分支 `feature/samsung-health-insights`。

## Anytime / CT4

稳定 transmitter sensorId 不改变。新增安装本地 UUID wear session，独立保存二维码归属、
录入时间、短 SHA256 标识、时间锚点、原始数据及算法连续状态。旧版本键采用增量迁移，
首次读取保留旧二维码但标为归属未确认；不要求清除 App 数据。

仅 live 路径观察大幅 ID 回退。至少三条不同、递增的低 ID，并有实际采样间隔经过、
推算开始时间晚于旧周期，才确认换周期。普通重连、重复回调、历史/乱序包和孤立低 ID
不创建新周期。候选期数据暂缓处理；手机重启后保留旧身份再重新确认，不用一次低值
立刻清空状态。由于协议没有可验证的物理探头 ID，这仍是软件推断，需要实机验证。

确认后先按旧时间轴排出待写历史，再归档旧周期元数据/二维码/原始采样/算法状态。
清除当前 raw、restoredGlucoseState、自动回填标记、引用校准、MK4 温度平滑/滤波器与
CT3 native port 连续状态；按新周期建立校准边界。原有 Room/native 血糖不删除。
不发送物理 reset、解绑或结束周期命令。新周期首次接收 live 建锚，后续 ID 严格按
3 分钟推进；不固定移动 +1 小时或 -75 秒。

旧二维码不会静默继承到确认的新周期。只有用户明确指定当前探头且录入时间与本次
推算启动相符的新码才保留；否则 CT4 MODEL 使用默认 K0=1.13。替换二维码前另存旧码
版本，即便先扫新码、稍后才确认换周期，也不会丢旧参数记录。
工厂校准格式与手动码可提供正 K/R；手动码不会再被标为工厂码。UDI 包装码只提供
元数据，不能以其占位参数改变 MK4 K0；历史合成参数是 DEFAULT，不能冒充工厂二维码。
恢复 MK4 连续状态时同时核对保存的 K0，旧 UDI/合成参数无法确认的滤波状态只重建本地
计算器，不平移、重算或删除已存血糖；有效工厂/手动码的兼容状态继续保留。
CT4 Auto MODEL 实际使用 K0；R 和电压模式属于 Raw 线性通道（无有效 QR 时 Raw K=.30，R=50）。

更新入口就在传感器详情「探头二维码与算法状态」，可扫码或输入，不需要删除发射器。
无效码在写入前拒绝。有效修改在驱动串行边界更新运行配置并重新初始化滤波器，已有
血糖不重算/删掉；下条实时采样采用新配置。相同码确认只更新归属信息，不重启滤波。
状态来自当前驱动 QR、实际 Result source、实际滤波器快照与周期存储，不用 hasQr 推断。
显示匹配是用户明确指定，不能证明包装与物理探头的工厂对应关系。

历史 CT4 使用独立模型按连续片段重放，每页一次线性遍历；回填乱序/重复不会推进
live MK4。完整 0..ID 前缀可以修正先前的暂存历史模型结果；本周期已输出的 live 值保留。
Room 缓冲按时间/优先级去重，既有 HC stable client ID/原生游标防止重传生成重复记录。
自动回填的理由、下一 ID 和范围随周期持久化，重启恢复；新周期重新执行近期与较早
前缀回填。旧请求返回的越界 ID 不导入新周期；同 ID 的跨周期物理载荷没有强会话标签，
极短的换探头竞态仍需实机确认。预热过滤沿用既有 commitReading 规则。

指尖校准保留历史锚点，`WearCalibrationBoundary` 只让采样使用自己周期内的校准点，
不删除旧校准历史。同步给手表的驱动校准锚点仅覆盖当前周期，手表独立采集时也按
自己的周期边界过滤，避免旧指尖校准跨探头使用。厂商依然分别决定什么事件证明新周期。

## Sibionics GS1-P2 / SIBIONICS2

按照硅基自身 probeCode 身份判断；添加／换探头流程中，已知旧码变成不同新码，
即使解码后的灵敏度相等也触发新探头状态。第一次补录此前未知的探头码本身不能证明换周期。
BLE-only 重连本身不清 probeCode，否则普通重连会失去有效校准。确认索引/时间轴重启时，
把原始 journal 改名归档，归档旧元数据/探头码，并清旧 manual sensitivity。
未获得新探头码则清当前旧码、使用驱动原有无探头码策略；新扫码则保留新码重新配置算法。

驱动自己原有的维护 reset 可以重置同一物理探头的索引，因此记录维护命令时间。
推算重启时间与该命令相符时保留探头码/灵敏度，不当作更换物理探头；其他已确认的重启
保守地失效旧码并要求重扫。已提供有效旧时间戳的重复 live idx=1 不能证明新周期。
归档失败暂缓新数据，不静默复用旧参数。不增加任何硬件 reset 操作。

2026-10-10 补齐 SIBIONICS2 传感器详情中的「扫描或更新当前探头二维码」入口，
支持摄像头、相册和粘贴。该入口让用户明确把码绑定到正在佩戴的探头；不同于
添加／换探头操作，补录和纠正参数不会改 transmitter 身份、开始时间、历史索引或
归档当前 journal。尚有待处理的换探头标记时拒绝当前周期补录，以免误覆盖新旧归属。
14 位码必须通过工厂校验；P2 旧式探头序列只从结构及 GTIN 校验通过的完整 GS1 标签提取，
再使用现有 P 格式灵敏度解码。发射器连接码不是校准码。有效参数变化沿用已有异步
连续重建路径，从本周期 journal 恢复，缺失输入则请求 BLE 连续补齐；完成前保留旧历史，
不会拿新建滤波器直接处理佩戴中段的 live 记录。原有手动灵敏度覆盖优先，不自动删除。
旧 QR 修订另外保存；同码重复确认不重算。首次明确确认旧记录只保存归属确认时间。
状态同时显示保存的工厂初始值、实际驱动的初始灵敏度及来源、V116A 内部有效灵敏度／索引
和重建等待情况；保存成功不等于已完成重算或已和官方显示一致。

## 其他驱动轻量审计

- AiDEX：标准化 X-serial 身份，provisioning 密钥按 bare serial 存储；配对与 wear-life 已有
  专用策略。当前代码没有足够证据证明同一 stable serial 换一次性探头，因此不扩大改动。
- MQ：显式 local reset 清易失 session、历史锚、K/B、引用 BG、索引与持久化 runtime。
  QR/配对材料仍属既有设备身份；没有确认的可复用探头身份协议，不盲目清凭据。
- iCan：以 DIS canonical serial 校正广告临时身份，并按 canonical serial 存 AES 材料；
  不以 BLE 地址作为最终探头身份。未发现本次可确认的同类复用污染路径。
- Ottai：认证签名、canonical sensor ID、按 sensor 的历史缺口账本隔离；激活已有单独授权。
  当前没有证据要求把连接或历史返回当作新的物理探头，不增加统一重置逻辑。

这些是源码审计结论，不是各品牌真实可复用硬件的兼容性认证。

## 必须实机验证

CT4 官方 App 新探头初始化后接管、三条 live 确认等待期、扫描/无扫码换探头、重启与
自动/手动回填、回填与实时并发、旧历史和 HC 数据完整性；GS1-P2 新码/无新码以及维护
索引重启。所有算法/归档/导出测试只是软件验证，不能代替真实 BLE 和佩戴周期证据。
