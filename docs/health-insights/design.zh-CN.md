# 综合健康时间线：设计稿 v0.1

状态：Android 第一版已实现，真机验证待完成。2026-10-09。

本文件保留完整产品设计；当前实现及尚未完成的图表交互见
[实施记录](implementation.zh-CN.md)。进入页面默认刷新间隔 5 分钟、默认读取 30 天已采用。

## 已确定的边界

1. SDK 留在用户本地，不上传 GitHub。含 SDK 的个人 APK 也不进入公开构建产物。
2. 所有设计与后续实现位于 fork 的新分支 `feature/samsung-health-insights`，
   继承 `build/custom-dub-final` 中的 HC、时间锚点、CSV 和 BLE 搜索修复。
3. 新增独立的「健康时间线」页面，把三星健康数据与 Juggluco 的血糖、已有日志按时间关联。
4. 首页以血糖、睡眠、运动等联动时间线为主。
5. 三星数据采用进入页面刷新与手动同步；第一版不增加定时后台同步。
6. 第一版暂定文件导出，目标分析客户端为 ChatGPT 等 Agent；实时 MCP 留待后续。
7. 单独一个「导出全部数据给 Agent」按钮，导出整合同步后的全部本地健康数据。
   读取类型和同步范围在数据源中管理；现有 HC 血糖同步继续独立工作。

## 页面入口与结构

在手机设置页增加「健康时间线」入口。页面右上角提供「数据源」，可管理三星读取。
可设置是否加入主导航；默认从设置进入，避免把现有手机底栏挤成六项。
第一版页面内部采用三个分区：时间线、分析、数据源。
页面保留一个独立的「导出全部数据给 Agent」按钮，所有分区均可使用。
第一版不显示 MCP 页或需要配置日期、类型、格式的导出流程。
沿用项目现有 Compose / Material 3、明暗主题、血糖单位和字体设置。

### 时间线（默认）

- 顶部：所选日期、时间跨度（日/周/自定义）、显示时区、刷新状态。
- 血糖为第一轨，保留现有原值/显示值与主传感器选择规则。
- 心率、血氧、皮温采用各自单位的轨道；睡眠阶段和运动采用区间条。
  各轨道共享横轴与游标，不将不同单位画在同一个纵轴上。
- 类别按钮控制可见轨道。仅看血糖时仍然可用；没有三星 SDK 的构建显示接入说明。
- 点击、拖动或通过时间输入选择游标，所有轨道定位到同一绝对时间。
  无覆盖时显示「该时间无记录」，不填 0，不跨长缺口插值。
- 点击运动或睡眠区间，打开详情：原始时间、来源、测量/汇总类型、对应血糖与上下文。
  可选择事件前后观察窗口；这些查看设置不缩小完整导出的数据范围。
- 日界线和当前显示时间使用所选 IANA 时区；原始记录的 offset 留在详情和导出中。
  跨时区与夏令时按绝对时间换算，不固定加一小时或减 75 秒。
- 不同传感器、不同 glucose 来源仍可辨认。三星血糖另列来源，不自动替代主 CGM 曲线。

### 分析

第一版提供可复核的描述性统计：区间血糖统计、睡眠/运动前后血糖、按日汇总、数据覆盖情况。
复用现有统计模块与用户目标区间，导出时带算法版本、参数和采用的血糖显示策略。
运动与睡眠只做时间上的关联，不把相关性写成因果结论。
数据不足时显示样本数、缺口和「不足以比较」，不生成空泛健康评分。
第一版的「分析」不要求内置大模型；用户的 Agent 通过完整数据包进一步分析。

### 数据源

三星读取总开关默认关闭；开启后检查本地 SDK、Android 版本、三星健康安装/版本、
开发模式连接与读取权限。缺少条件时提供对应操作说明，已有本地数据仍可查看。

类别列表分为运动、睡眠、生理指标、饮食饮水、汇总目标、个人资料。
支持全选健康数据和逐项选择；运动位置与个人资料单独选，不混入普通全选。
每项显示：是否启用、授权、最后成功读取时间、当前数据范围与记录/序列数量。
可区分关闭、未授权、SDK 不支持、成功但无记录、成功、部分完成、失败。

默认选已实测的心率、血氧、睡眠、运动、步数、皮温；完整接入范围见能力清单。
「全部」指当前官方 SDK 可读取的数据，不能承诺三星健康界面上的所有指标都开放。
SDK 1.1.0 的 25 个类型/权限入口中，运动位置仅是额外授权项；步数、目标等走汇总接口；
个人资料走专用读取。ECG 波形、压力等不能仅凭健康界面存在就声明可取。

首次导入默认最近 30 天，可改成 3/7/30/90 天或自定义；同步任务分段、可暂停并续传。
进入页面仅在距上次尝试超过 5 分钟时刷新，手动刷新不受该限制。
这些是初始建议值，设计讨论可以调整。任务并发合并，避免返回页面触发多个读取。

### 单按钮完整导出（第一版）

按钮文案：「导出全部数据给 Agent」。点击后依次进行：

1. 合并或排队一次已启用数据源的同步，显示进度，等待正在进行的同步提交完成。
   不暗中扩大导入历史或申请新权限；仅刷新用户已选择的同步范围。
2. 捕获同一导出任务的各源一致快照，固定截止时间与源版本。
3. 流式生成一个 ZIP，完成后打开系统保存/分享，用户选择保存到 Download 或发送文件。
   该操作不自动向 ChatGPT 或其他网络服务上传。

「全部」明确指本地保留的全部有效健康记录，包括所有 CGM 来源/传感器及可用值通道、
已同步的全部三星类型与子序列、已有 Juggluco 日志，以及关联和统计概要。
它不受当前页面日期、可见轨道、事件窗口或主传感器显示筛选限制。
已有缓存即使其读取开关后来关闭，也仍在完整数据包中，并标注最后同步时间与状态；
已由用户删除或由来源明确删除的数据不再包含。
个人资料/路线只有在此前明确选择读取并成功同步后才会进入数据包；导出按钮不额外开启它们。

「全部本地数据」不等于三星账号中的全部历史；尚未导入、未授权、SDK 未开放或设备已清理
的时间范围均在清单中注明，不能被标成完整覆盖。同步部分失败时可导出已有数据，但清单和
概要必须明确标为部分同步，并列出错误、最后成功时间和未覆盖范围，不能报告为全部成功。

ZIP 固定包含 JSONL 记录/完整序列、关系、概要 JSON/Markdown、字段与 schema、数据源状态、
各类型实际时间范围、数量、质量和校验值。Agent 可先读取清单和概要，再按需读取分类型文件。
既存未映射的健康字段单独记录并标明单位/语义未知，不能静默丢弃或猜测含义。
SDK 调试对象、日志及其他诊断材料不混入健康数据；原始诊断导出可另行设计。
不抽稀完整序列，不按聊天上下文长度静默截断。文件过大时显示大小与完整性；空间不足等
失败不发布半成品，保留可重试状态。范围导出、概要单独导出和 CSV 作为后续扩展。

默认替换传感器/设备等识别码；这不是承诺健康记录已不可识别。
不导出账号、BLE 配对密钥、MCP 凭据或 app 签名密钥。
ZIP 中的说明和 schema 允许 Agent 从元信息开始，按需读取序列，避免一次读入巨大嵌套对象。

### 后续候选：Agent / MCP（不纳入第一版）

以下只保留接入约束和工具草案，第一版不实现服务器、连接通道或网络共享设置。

官方自定义 MCP 文档目前说明通过 ChatGPT 网页添加与使用连接。服务必须通过 HTTPS
地址或 Secure MCP Tunnel 可达，不能把手机的 `127.0.0.1` 直接交给 ChatGPT。
手机浏览器可作为待验证入口；Android ChatGPT App 是否可调用该个人连接需真实验证，
不能仅凭安装了 App 就声称支持。具体账号与工作区的可用性也必须检查。

连接页分为三种路径，第一种是优先调查候选，尚未确定或实现：

- **ChatGPT · 安全隧道**：本地数据与查询服务仍在手机，通道向外连接 OpenAI。
  官方要求 Platform 的 tunnel ID、运行凭据及对应组织/工作区权限。
  必须先确认官方客户端或兼容实现能在 Android 上运行、联网并维持生命周期；
  官方文档描述的桌面/服务器部署不能直接当作 Android 支持证明。
- **ChatGPT · HTTPS 网关**：由用户控制的服务提供稳定 HTTPS MCP 与 OAuth，手机
  向网关建立受限外连通道，按请求查询本地数据。网关不默认上传或保存整套历史，
  但调用返回的数据仍会经过网关与 ChatGPT；需另行确定部署、授权与可用性。
  不能用一个公开无认证端点或 URL 中的密钥替代正式访问控制。
- **兼容本机客户端**：只绑定手机回环地址，例如 `http://127.0.0.1:18741/mcp`。
  供同机支持 Streamable HTTP 与认证配置的 MCP 客户端使用；这不是 ChatGPT 的直连入口。

第一版采用上面的单按钮导出。以下连接页面仅供后续实时接入时参考。
页面提供目标客户端、连接方式、准备状态、允许的类型与日期范围，以及开启/停止共享。
未满足接入条件时显示具体准备项，不显示虚假的“已连接”。连接与共享默认关闭。
运行通知提供停止操作；停止或撤销授权后拒绝新查询和已存在快照访问。
本机模式生成随机访问凭据；ChatGPT 路径按官方支持的认证方式实施，健康数据采用
OAuth 等受支持的授权机制，不假设 ChatGPT 允许手填任意 Bearer 请求头。
真实凭据只在需要的受控端保存，不进入导出或 Git；不开启宽泛 CORS。

只读工具覆盖状态、字段说明、时间线、记录、序列、区间统计与事件上下文。
返回结果包含 snapshot ID、各源采集时间、覆盖与缺口；分页固定在同一快照内。
血糖更新进入本地库后，下一个新查询可见；三星数据仍按照进入页面/手动读取刷新。
Agent 查询不暗中打开授权页或触发三星读取，数据陈旧时返回明确状态。

MCP 启动和持续运行须验证 Android 16 的前台服务类型与生命周期，不能借用或关闭 CGM
采集服务来管理 MCP。手机系统终止服务时，不承诺持续在线；连接页明确显示已停止。
需要用用户的真实 ChatGPT 账号、网页/手机界面及选定通道完成互通验证。
MCP 的 JSON 返回和 JSONL 导出共用同一数据模型；普通 HTTP JSON 接口不能冒充 MCP。

## 存储、同步与关联

三星数据进入独立的手机数据库，保存记录、子序列、关联、来源与每类型同步状态。
读取/导出/分析在后台线程执行，不能阻塞 BLE 或修改 Anytime 的 session 锚点。
血糖读取现有 HistoryRepository 和主传感器呈现规则；不复制重写 CGM 原始历史。

优先使用官方 readChanges 的 UPSERT/DELETE，分页全部成功并写入后才前移同步游标。
按更新时间拉取变化，不能仅看最近一次测量时间，避免漏掉旧睡眠的修订。
首次回填与增量之间设置重叠和补查；失败、未授权、空响应不等于删除旧数据。
步数、日目标等不提供 readChanges 的类型按日重算；完整新结果替换同范围旧汇总。
只删除官方明确删除的记录，不因部分查询遗漏推断删除。

同源去重键是 provider + data type + SDK UID。直接和睡眠关联读取同一条数据时只存一次，
睡眠关系另存。运动序列、睡眠阶段、血氧/心率分段值保留，不只留均值。
子序列随其父记录原子替换。时间戳相同的不同测量不简单合并。
不同来源的三星/Jugg 血糖或饮食记录不凭时间相近自动去重；保留来源并按明确规则关联。

## 数据格式

采用项目自有、带版本的 canonical schema，而不是让 Agent 理解 SDK 的 getter 名称。
公共记录包含 ID、类型、时间模型、来源、明确单位的测量值、粒度、质量、关联与序列引用。
时间模型区分绝对时刻/区间、本地日期和当前资料快照，不为只有日期或无时间的资料伪造时间。
原始 epoch/UTC、offset 与 SDK 原字段可追溯；缺失值用 null + 原因，不能变成 0。
完整定义与合成示例见 [data-contract.md](data-contract.md) 和 [record.schema.json](record.schema.json)。

## 实现位置与验收

- `Common/src/mobile/.../ui/health/`：Compose 页面与状态模型。
- `Common/src/mobile/.../data/health/`：独立数据仓库、统一模型、分析与导出。
- 可选 phone-only Samsung adapter：仅这里引用 SDK，其余代码通过 SDK-free 接口调用。
- 完整导出：独立后台任务，共用只读模型，不能关闭 CGM 或修改 HC 写入状态。
- 后续手机 MCP：独立启动/停止生命周期，不纳入第一版。
- 公共仓库只放代码、schema、合成样本及自行准备 SDK/授权的说明。

实施分为可审核的提交：可选构建与入口；六类已验证数据的存储/去重/增量；
完整 SDK 能力适配；联动时间线与分析；单按钮完整导出与真实文件验证。
这描述实现顺序，不减少最终接入全部官方可读取类型的目标。

验收必须覆盖：无 SDK 普通 phone/wear 构建、带 SDK 的 arm64 personal DUB 构建；
UTC+7/+8 与夏令时、分页、修订和删除、重复关联、拒绝权限、缺口、停止/恢复同步；
导出使用同任务快照；查看筛选不影响完整导出；全部来源/序列/日志数量与校验值可核对；
同步失败/空数据/保存取消/磁盘不足有明确状态；分享与保存文件可在 ChatGPT 中真实读取；
HC 与 BLE 继续正常工作。首次整体集成 APK 的读权限需重新授予，不能沿用 probe 的权限。
